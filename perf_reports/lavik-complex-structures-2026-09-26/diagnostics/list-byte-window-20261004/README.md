# List 按字节限制的读取窗口（草稿 PR #269）

[PR #269](https://github.com/eloqdata/lavik/pull/269) 基于 [PR #267](https://github.com/eloqdata/lavik/pull/267)。本页保留初始扫描与后续三轮交替复测。不能由单个场景的提升推断整体达到其他系统的水平。

## 改动与边界

每批最多从 16 页扩大到 64 页，同时增加 512 KiB 编码载荷上限；单个超大页单独读取。任务数组移出 List 点读写共用协程。每个窗口新增一个辅助协程，所有已启动子任务仍完整回收，结果保持顺序，恢复父协程后继续检查数据代际。没有磁盘格式修改或载荷缓存，读取同样的数据；变化主要在 I/O 重叠和任务调度。

[构建来源与二进制 SHA256](list64-versions.json)：旧版 `ff9e3655`，新版 `4863c98d`。新版另包含独立的冷恢复修复及测试时序修正，前台 List 路径的增量仅为读取窗口改动。两者均关闭测试和故障注入。

## 独立 perf

[采样比较](list64-profile-comparison.json) · [新版本样本摘要、计数器与命令](range-profile/)。25 秒 task-clock 采样与 30 秒计数器窗口为单独诊断，不混入吞吐曲线。

- Worker::RunOnce 的 self CPU 占比：23.25% → 19.21%。
- PollStorage：12.98% → 10.76%。
- memmove：8.12% → 8.16%；分配器：1.44% → 1.74%。辅助协程有分配成本，不能声称所有分配/复制都减少。
- 两者均为每次 LRANGE 14,125 次物理读、约 124.3 MB，0 次写。

这些是包含轮询和内核工作的采样比例，不是延迟比例，也不是每条命令的绝对 CPU 时间。读取等待减少仍需交替吞吐与尾延迟复测支持。

## 验证

[完整验证记录](list64-validation.json)：启用故障注入时 ordered 套件 106 项通过、1 项可选大测试跳过，恢复套件 28 项通过；实际性能二进制另通过 2 项范围读取与 3 项命令/阻塞/事务测试。覆盖半途启动失败、读取失败、暂停读取生命周期、内存准入和恢复。

新增 16 × 4 MiB 元素用例在 96 MiB 服务器内存、关闭独立客户端配额下，通过重启后逐字节及顺序检查。旧版也通过此用例；它用于超大页面路径覆盖，不代表已复现并修复旧版 OOM。

后续控制组与交替复测见下文。PR 状态需结合回归、收益一致性和 CI 单独评估，图中仍标为草稿。
