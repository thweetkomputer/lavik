# HSET I/O 计数诊断

PR #222 `5a5c749d`，500 × 100 MiB Hash、128 B field、320 连接，每点 20 秒。
服务端启用 metrics，只在每个 memtier 测点的前后读取，不在测点内抓取。
这个诊断点不混入主图的八秒结果。

- HGET：562,933 QPS；每条完成命令均摊 1.00 次存储读，约 6.62 kB。
- HSET：43,115 QPS；每条完成命令均摊 0.312 次存储读、2.119 次写，约 10.95 kB 读、14.22 kB 写。
- 每条 HSET 均摊 2.116 次逻辑 fdatasync；VWC=0 路径在软件中完成，因此这不是 NVMe FLUSH 命令数。

计数来自全部 worker，包括后台清理。统计窗口还包含客户端连接建立、结果收集和尾部清理，
不能把均摊数解释为每条 HSET 固定发生的前台 I/O，也不能仅凭读次数断定瓶颈。
它显示写放大和提交/清理需要进一步检查，并不支持把吞吐差距简单归因于每次 HSET 都要读盘。

`summary.json` 保留精确差值与分母；原始 Prometheus 快照、memtier 摘要、源代码与二进制 provenance 同目录。
