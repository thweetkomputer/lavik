# Hash/Set 单路由替换：大对象独立 perf

[加权 self / I/O 汇总](hash-route-large-perf-summary.json) · [汇总脚本](summarize-hash-route-perf.py) · [原始采样清单](hash-route-replace-profiles-recorded.json)

全部 144 个干净观测完成后，父 `19496654` 和候选 `27c65ff9` 各独立恢复 500 个 100 MiB / 1024 B key 并重启，在 c320 采集 HSET 或 SADD/SREM。每组 30 秒命令/计数窗口，25 秒、99 Hz、16 KiB DWARF 的逐 worker task-clock；四组均完成全部 key 基数、来源、客户端/服务端调用数、零命令错误及正常退出校验。顺序固定父后候选，路由种子及布局不同，诊断 QPS 不进入干净对照。

## 每个完成命令的存储计数

| 计数 | HSET 父 | HSET 候选 | Set 父 | Set 候选 |
|---|---:|---:|---:|---:|
| 读操作 | 0.234 | 0.254 | 0.020 | 0.014 |
| 写操作 | 0.645 | 0.636 | 0.221 | 0.278 |
| 读取字节 | 7052.381 | 8115.735 | 507.118 | 292.723 |
| 写入字节 | 7841.327 | 8510.608 | 3300.821 | 2423.334 |

分母分别是窗口内 HSET 或 SADD+SREM 的完成调用数，并与客户端请求数及 INFO 一致。重启后的 before 没有这些写命令计数，按零处理；存储计数两端均要求存在。Set 包含无操作命令，不能当作 durable mutation 数。存储差分包含后台活动、计数边界和独立数据布局影响；CPU 与计数窗口不同，不计算 CPU/命令。

目录路径更新和分配器 self 占比下降符合减少目录遍历的方向，但不能解释所有干净对照中的吞吐回退：大 Hash 的读写字节/命令在这次诊断反而增加，Set 的读写字节降低、写操作数增加。候选 Set 记录 29,824 次提交高水位入队事件，父为 0；提交批次数也从 267,852 变为 468,180。该计数不是等待时长，其他干净窗口无高水位仍有回退，因此不能把吞吐变化归于单一机制。

PR #276 继续保持草稿。小 Hash HSET 的两组独立采样仍排队，用于检查该范围的分配/目录热点；本次大对象采样不能代替它。
